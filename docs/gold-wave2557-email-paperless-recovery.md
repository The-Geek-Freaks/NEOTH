# Email-to-Paperless recovery (W2557)

The existing default-off email-ingest cron now uses the daemon's existing authenticated WAL writer to claim a stable mailbox unit before one document POST. A claim binds canonical mailbox/account identity, Message-ID (or UID plus UIDVALIDITY), sanitized body, deterministic title and canonical destination. Repeating or changing an already claimed unit never grants another POST.

The adapter supports the repository-pinned Paperless-ngx 3.2.1 / API 10 contract. Before claiming a new unit, a bounded authenticated document lookup verifies the version headers and response shape. An unsupported server, malformed request, inaccessible API or body larger than 2 MiB receives no new claim or POST. This implementation does not upgrade a user's Paperless installation.

Uploads carry an opaque deterministic original filename derived from the complete request binding. Recovery queries that filename, requires exactly one complete result, checks the returned original filename locally, downloads the original file with a strict 200 response and hashes every byte within a 2 MiB limit. Only matching bytes permit a second, ordered, authenticated completion receipt containing the document identity and request witness. Only its durable acknowledgement permits the cron to mark local processing complete. HTTP 2xx and task UUIDs are not completion evidence. A document can be reconciled after a lost response or restart without a second POST.

There are at most 128 unresolved Paperless claims. The writer reconstructs the open set from authenticated primary WAL, validates every completion against its actual preceding request and frees capacity only on an exact completion. At capacity, later first uploads wait while existing units can still reconcile. Missing or ambiguous documents, changed content/destination, HTTP failures, cancellation and incomplete WAL remain pending without an automatic POST retry. An operator must resolve a permanently absent or conflicting external effect; no automatic reset or unsafe resend command is added here.

The existing supervisor retains a mailbox-bound round-robin UID selection cursor. It cycles through currently unseen messages, including older pending units, without changing the IMAP server's Seen flag. UIDVALIDITY changes reset selection, and UID fallback identities include that epoch. The cursor is a volatile progress hint, not effect authority: repeated process crashes can restart selection from the newest UIDs. The existing legacy local seen projection is retained; this slice does not migrate historical unscoped seen rows.

The completion evidence means the exact original bytes were observed at that Paperless instance during reconciliation. It does not prove which actor created a matching document or guarantee that another actor will not later alter or delete it.

Validation: 22 new Rust cases cover writer concurrency/cancellation/restart, request drift, completion ordering and capacity, real loopback HTTP recovery, API/filename/content/status rejection and UID selection. Three existing WAL/companion cases check compatibility. All 25 are registered in `gold-wave2557-email-paperless-recovery-tests.json` and run with `imap_fetch` in the existing Paperless product workflow. Twenty new cases also enter the portable native matrix; two IMAP selection cases require the feature. Static review repaired the missing completion path, non-200 empty-download acceptance and mismatched completion-capacity release. Hosted compilation and execution remain pending at initial publication. No local runtime was executed.
