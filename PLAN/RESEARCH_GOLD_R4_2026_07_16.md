## GOLD-R4-05 Full GUI/CLI capability parity audit

**State of play:** The GUI ships 10 live Settings tabs (Chat, Hemispheres, Channels, Skills, Plugins, Memory, Privacy, Cluster, Config, Code Sessions) plus separate nav panels for Doctor/Status/Security-audit (`tabs.slint:148–290`) and Hardware resources (`tabs.slint:36–89`). ## GOLD-R4-06 Buddy product-grade utility audit

**State of play:** The buddy/companion surface is substantially built. The WAL event bus (gui_stream.rs) tails `neothd wal follow --types …` across 35 opcodes and maps them to 24 GuiActivity variants; `every_activity_maps_to_a_rendered_mood` pins the vocabulary exhaustively. Overlay drag, position-persist, compact/speech-bubble resize, and the always-on-top AlwaysOnTop wiring all landed. The quick-action menu (B4) renders 4 items; right-click opens the command palette (H12); the state-ring (H10) with VU stagger and trailing sweep is in buddy.slint. Every mutation that originates from a main-window panel goes through gui_action::run_neothd_json_action, which requires exit 0 plus a typed JSON ACK with field binding — the structural test at gui_action.rs:762 locks 25+ named actions. The five product-grade gaps are: (1) no approvals surface in the overlay or dock — ConsentGate fires a pink badge but has no accept/deny UI; (2) no notification center — unread-count badge exists but Rust never populates it and ChannelIngress has no queue; (3) the overlay carries zero channel or automation status; (4) voice/mic entry is an explicit stub (status_text only); and (5) there is no in-overlay cancel — the overlay spawns its own chat subprocess with no stored handle, making abort impossible while the main window is hidden. Two boundary concerns: the quiet-hours quick-action toggle writes freedom.yaml directly (not via CLI ACK), and the overlay send path spawns neothd chat --stream raw with no typed ACK, so a mid-stream consent gate blocks invisibly with no abort surface.

## GOLD-R4-09 DAU / Accessibility / Polish Gate — UI Audit

**State of play:** The sidebar is the single largest accessibility gap: all 28 NavBtn instances (app_shell.slint:96) and all 8 settings TabButton instances (settings.slint:223) are TouchArea-only with no FocusScope, no accessible-role, and no accessible-label, making 22 of 28 tabs completely unreachable without a mouse. Keyboard shortcuts Ctrl+1..5 + Ctrl+, reach only 6 destinations; when the sidebar is collapsed the shortcut-covered tabs still work but nothing else does. Four action buttons in tabs.slint (lines 120, 187, 228, 269) share the same defect and also lack cancel/abort affordances while running. Error text surfaces raw CLI stderr lines (anyhow chains, Windows paths, exit codes) verbatim as toast body text through gui_action.rs:52-55 with no sanitization layer. In settings.slint, at least 18 label-column Text elements carry hard-coded pixel widths (130–200 px) that will clip German/French translations without wrapping. Light-mode text-tertiary (#6f726a on #fbfaf6) tests at roughly 4.17:1 — below the WCAG AA 4.5:1 threshold, and far below the 7:1 required for the 11 px mono eyebrow labels that use this token. suppress_console_window is consistently applied to all subprocess spawns via spawn_neothd_plain, so terminal-flash is not an issue. Slint logical-pixel sizing handles high-DPI automatically, but two 10 px hard-coded font sizes in app_shell.slint bypass the font-size-override operator token.
