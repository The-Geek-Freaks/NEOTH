4 agent diagnoses were lost to a host BSOD and re-derived manually):

1. **Banner in --version stdout** — `info!(version=…, "{BANNER}")` fired
   before `Cli::parse()`; clap handles --version inside parse, so both
   binaries emitted a timestamped INFO line and the byte-equality
   contract failed. Fix: banner after parse (production).
2. **macOS lane is NEW** — it surfaced long-standing macOS-only bugs for
   the first time:
   - `prepare_portable_marker` staged in global temp → `/var` symlink →
     install-transaction reparse guard bail. Every real macOS portable
     install would have failed. Fix: `tempdir_in(resolved_root)`
     (production).
   - Skills watcher: FSEvents reports `/private/var/...` canonical
     paths, `event_is_skill_relevant` compared against the `/var/...`
     spelling → all 4 watcher tests timed out. Fix: canonical alias via
     existing parent (production; no-op on Windows).
   - `killed_transaction…` test fed a non-canonical tempdir to the
     reparse-guarded transaction. Fix: canonicalize in test.
   - `stricter_omi_reload…`: drop-then-rebind ephemeral port raced with
     sibling nextest processes (macOS reassigns freed ports first).
     Fix: bounded 3-attempt boot retry, non-port failures still panic.
3. **Self-matching source guards** (from 0ca585b8): tts.rs "reqwest",
   gui main.rs "on_chat_channel_switched" — the banned literal appeared
   in the assert itself inside `include_str!` of the same file. Fix:
   concat/split idiom (same as the passing sibling guard in cli/tts.rs;
   the tts fix also had to split "api.elevenlabs.io", which the
   diagnosing agent missed).

   shipped; web_fetch error phrasing changed to "invalid HTTP URL" via
