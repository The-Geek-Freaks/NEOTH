# NEOTH GUI Audit — 2026-05-20

Platform: Desktop (Slint, Windows/Linux/macOS)
Scope: wizard (9 steps) + settings (9 tabs) + chat surface + shared components
Operator target: non-developer ("noob")

---

## CRITICAL — Blocks operator from completing wizard

### G-1: Identity screen — placeholder mistaken for value
**File:** `SRC/neothd-gui/ui/main.slint:408-411`
**Category:** Logic / UX blocker
`LineEdit` carries `placeholder-text: "alex"` but `enabled` gate reads `root.operator-id != ""`. A noob sees the grey text "alex", assumes it counts, clicks Continue — button stays disabled with no explanation. Operator is silently stuck.
**Fix:** Remove the placeholder entirely (or change it to something unambiguous like `"your-handle"`). Add a red caption below the field when `operator-id == ""` and the user has focused then left the field: `"Required — enter a short lowercase handle."` Cap the field to 32 chars.

---

### G-2: License screen — Card feels empty, no scroll, no license text
**File:** `SRC/neothd-gui/ui/main.slint:357-387`
**Category:** Layout / Trust blocker
The `preferred-height: 200px` Card contains one line of prose + a CheckBox. The remaining ~150 px is dead air. Worse: no actual license text is displayed. A noob asking "what am I agreeing to?" sees only the link to a GitHub URL — which they cannot click because it is plain text inside a `Text` element (Slint has no inline hyperlink).
**Fix:** Replace the single-line prose with a brief plain-language summary of MIT/Apache-2.0 (3–4 bullet points). Add a `NeothButton { label: "View full text →"; primary: false; }` that opens the URL via `std::process::Command::new("xdg-open"/"open"/"start")` from Rust. Fill the vertical rhythm with this content so the card is not empty.

### G-3: ComboBox brand violation — Autonomy + Provider screens show light-mode widget
**File:** `SRC/neothd-gui/ui/main.slint:454-466` (Provider), `492-509` (Autonomy)
**Category:** Dark-mode spec violation (CRITICAL)
`ComboBox` imported from `std-widgets.slint` renders with its own internal background that ignores `Theme.bg-card`. On all platforms this produces a white or light-grey popup against the dark window — a jarring spec violation and a readability failure (black text on near-white, but inside a dark window context the contrast flip is disorienting).
**Fix:** Wrap `ComboBox` in a custom `NeothComboBox` component in `components.slint` that uses a `Rectangle` overlay strategy or, if Slint does not allow full style override, switch to a vertically-stacked `NeothButton` radio group (5 items for Autonomy, 7 for Provider). Radio group is also more discoverable for noobs than a dropdown.

---

### G-4: Channels screen — only Telegram selectable; 8 messengers missing entirely
**File:** `SRC/neothd-gui/ui/main.slint:537-588`
**Category:** Feature completeness / Operator expectation mismatch
Brand spec, SPEC_channels.md, and memory notes list WhatsApp, Discord, Signal, Matrix, iMessage, LINE, Messenger as planned channels. Only 4 checkboxes exist: CLI, Telegram (enabled), Slack (disabled), Keet (disabled). Operators coming from the docs or marketing copy will not understand why most channels are absent.
**Fix (two-step):**
1. Add greyed checkboxes for WhatsApp, Discord, Signal, Matrix, iMessage, LINE, Messenger. Each carries a tooltip-style caption: `"Coming in v0.2 — adapter in progress"`.
2. For the disabled channels (Slack, Keet, and the new ones) replace the cryptic dev note ("adapter scaffold only, not shipping in v0.1") with a user-readable caption: `"Not available yet — tap to join the waitlist"` or simply `"Coming soon"`. Technical build notes must not surface to noob operators.

### G-5: Settings panel — no exit / back path
**File:** `SRC/neothd-gui/ui/settings.slint:308-647`
**Category:** Navigation trap (CRITICAL for noobs)
`SettingsView` exposes no callback and renders no button to return to Chat. Once an operator navigates to Settings (via ⚙ in the sidebar), the only documented exit is clicking ⚙ again — but ⚙ is in the Chat sidebar, not visible inside Settings. A noob who reaches Settings is trapped until they know to press Escape or close the window.
**Fix:** Add a `callback back-clicked` to `SettingsView`. In the sidebar header area, above the tab list, insert a `NeothButton { label: "← Chat"; primary: false; }` that fires `back-clicked`. In `main.slint` connect: `back-clicked => { root.step = WizardStep.chat; }`.

## HIGH — Broken, unreadable, or misleading

### G-6: FooterBar renders raw ANSI escape sequences on all screens
**File:** `SRC/neothd-gui/ui/main.slint:846-853`, `SRC/neothd-gui/src/main.rs:556-576`
**Category:** Rendering defect
`probe_hardware_via_subprocess()` already sets `NO_COLOR=1` and `RUST_LOG_STYLE=never` (main.rs:560–563), which is correct for the `hardware` subcommand. However, the `kanban list/show` and potentially other subprocess calls (lines 427–431, 471–475) do NOT set the same env vars. If the daemon binary's tracing-subscriber emits ANSI to stdout on those paths the FooterBar and status line will contain escape sequences. Additionally, the FooterBar `Text` component has no `overflow: elide` — a long hardware string can overflow the 36 px strip.
**Fix:** Extract a helper `subprocess_with_no_color(bin, args)` that always passes `NO_COLOR=1 / RUST_LOG_STYLE=never / CLICOLOR=0` for every subprocess call. Add `overflow: elide` to the FooterBar `Text` (components.slint:305).

### G-7: Autonomy screen — "Picked:" Card is oversized, single line
**File:** `SRC/neothd-gui/ui/main.slint:510-521`
**Category:** Layout / Vertical rhythm
The `Card` that shows `"Picked: standard"` uses no `preferred-height` constraint but renders at whatever minimum Card height is (~50 px), yielding 40 px of empty card for a 12 px text line. Combined with the floating ComboBox above it (G-3), the screen looks unfinished.
**Fix:** Replace the Card with an inline explanatory block below the ComboBox: a `Text` with the autonomy level in `accent-green` next to a one-sentence plain-language description (e.g. `"standard — Writes to ~/.neoth allowed; every shell command needs your approval."`). Remove the Card entirely.

### G-8: Code Sessions board — columns too narrow, titles wrap to one word per line
**File:** `SRC/neothd-gui/ui/settings.slint:528-562`
**Category:** Readability / Layout
5 `KanbanColumn` instances share the full width (minus 320 px feed rail) with `spacing: Theme.space-tight` (8 px). At the minimum window width of 720 px: available = 720 − 32*2 (screen padding) − 16 (SettingsView left pad) − 220 (sidebar) − 32 (HLayout padding) − 320 (feed) − 4*8 (gaps) = ~32 px per column. Even at 1280 px wide it is ~130 px per column. `KanbanTaskCard` has `padding: Theme.space-tight` (8 px) on all sides — a 15 px body font in 130 px − 16 px = 114 px clips on 2–3 words.
**Fix:** (a) Reduce feed rail to 260 px and make it collapsible. (b) Increase `KanbanTaskCard.height` to 90 px min and set `padding: Theme.space-base` (16 px). (c) Add horizontal scroll to the board `HorizontalLayout` so columns never go below 160 px: wrap the 5-column layout in a `ScrollView { horizontal-scrollbar-visible: true }`.

### G-9: Chat send button visually appears disabled when composer is empty
**File:** `SRC/neothd-gui/ui/chat.slint:227-237`
**Category:** UX / Feedback
`NeothButton { enabled: root.send-enabled && root.draft != ""; }` is logically correct. But because `NeothButton` renders disabled state as `opacity: 0.4` (components.slint:33), a noob opening Chat for the first time sees a dim "Send →" button and may assume the chat feature is broken. No tooltip or hint explains "type a message first."
**Fix:** When `draft == ""` keep `opacity: 1.0` but grey the label text (already handled by the disabled color path). Add a `placeholder-text` to the `Composer.input` LineEdit that reads: `"Type a message — press Enter or click Send →"`. This gives an affordance without adding UI elements.
Current placeholder is `"Type a message — \`/\` opens commands."` — this is good, verify it is visible at full opacity even when the button is dim.

### G-10: Chat surface has no header / active-channel indicator
**File:** `SRC/neothd-gui/ui/chat.slint:264-358`
**Category:** Context awareness / Orientation
The main pane (scrollback + composer) shows no title or breadcrumb for the active channel. If an operator switches from CLI to Telegram in the sidebar, the scrollback area gives no visual confirmation of which channel they are viewing. The only indicator is the accent-green left bar on the sidebar item, which is outside the main reading area.
**Fix:** Add a thin `HorizontalLayout` above the `ScrollView` (height 40 px) showing the active channel name in `text-primary` + a status indicator dot. Example: `"● Telegram"` with the dot in `accent-green` when connected, `text-dim` when disconnected. Wire via `root.channels[root.active-channel-index]`.

### G-11: Welcome screen — NeothButton "Continue" always enabled
**File:** `SRC/neothd-gui/ui/main.slint:340-347`
**Category:** UX consistency
Every other wizard step gates Continue on user input. Welcome Continue fires immediately with no action required — that is correct — but there is also no `← Back` button. An operator who reaches Welcome from Mode Selection and wants to go back has no affordance.
**Fix:** Add `NeothButton { label: "← Mode"; primary: false; clicked => { root.step = WizardStep.mode-selection; } }` on the left side of the footer `HorizontalLayout`, matching the pattern of all subsequent screens.

### G-12: Settings Config tab — `provider-current` read-only display only
**File:** `SRC/neothd-gui/ui/settings.slint:605-644`
**Category:** Settings parity gap
The Config tab shows `"Active provider: claude_cli"` as plain text but provides no way to change it within the GUI. The tab comment says "Raw freedom.yaml view" but no file content is shown. The operator is told to "Edit freedom.yaml directly with your editor" — this breaks the noob-operator contract (HARD RULE: noobs never touch YAML directly).
**Fix (near-term):** Add a `ComboBox` (styled per G-3 fix) for provider selection that calls a `provider-changed(string)` callback. Medium-term: add an autonomy level selector here too, mirroring the wizard step. Minimum: render the current `freedom.yaml` content in a `TextEdit` (read-only) so the operator can at least see what the daemon is reading.

## MEDIUM — Subpar, reduces polish or clarity

### G-13: ProgressIndicator total-steps logic flips from 8 to 7 silently
**File:** `SRC/neothd-gui/ui/main.slint:97-107`
**Category:** UX confusion
When `provider-choice == "claude_cli"` and no channels are ticked, the bar jumps from "Step 6 of 7" to "Step 7 of 7" (done), skipping the Keys screen. The step counter changes denominators mid-flow without any announcement. A noob who saw "8 steps" on the Welcome screen will notice the count changed.
**Fix:** Keep `total-steps` fixed at 8. When the keys screen is skipped, mark it as auto-completed with a brief status line on the Done screen: `"Step 7 skipped — no API keys needed for claude_cli."` This prevents the denominator shift.

### G-14: ModeCard glyph images reference SVG assets that may be missing
**File:** `SRC/neothd-gui/ui/main.slint:245-246, 254-255`
**Category:** Build-time risk
`@image-url("assets/glyph_gui.svg")` and `@image-url("assets/glyph_cli.svg")` — if these files are absent the Slint compiler silently uses a transparent placeholder. Operators see two empty 140 px boxes as their first impression of the product.
**Fix:** Confirm the SVG assets exist at `SRC/neothd-gui/ui/assets/`. If not, add them or replace with inline SVG paths rendered via `Path {}` elements so the build is asset-free.

### G-15: Keyboard navigation — no explicit Tab order or Enter-key handling in wizard
**File:** `SRC/neothd-gui/ui/main.slint` (all wizard steps)
**Category:** Keyboard accessibility
Slint's default Tab order follows component declaration order. The Identity LineEdit → Continue button path works. But the License CheckBox is not reachable via Tab in a consistent order because it is inside a `Card > VerticalBox > CheckBox` hierarchy without an explicit `focus-policy`. No screen handles `key-pressed(key) => { if (key.text == "\n") root.step = ...; }` for Enter-to-advance.
**Fix:** On each wizard step that has a single primary action (Identity: Enter confirms the LineEdit and advances; License: Space toggles CheckBox), add a `FocusScope { key-pressed(e) => { if (e.text == "\n" || e.text == " ") { ... } } }` wrapper or use `LineEdit.accepted` (already wired in Composer — replicate in wizard inputs). Document Tab order explicitly with comments.

### G-16: CheckBox and LineEdit in std-widgets — light-mode surface color
**File:** `SRC/neothd-gui/ui/main.slint:369, 408-412, 547-565, 611-630`
**Category:** Dark-mode spec violation (same root as G-3 but lower blast radius)
`CheckBox` and `LineEdit` from `std-widgets` use platform-native backgrounds. On Windows this renders a white input box and white checkbox area inside an otherwise dark card. The operator's dark-only brand promise is broken.
**Fix:** Create `NeothCheckBox` and `NeothLineEdit` wrapper components in `components.slint` using `Rectangle + Text + TouchArea` (CheckBox) and `Rectangle + TextInput` (LineEdit), styled with `Theme.bg-card`, `Theme.border-subtle`, and `Theme.accent-green` focus ring. This is the same fix path as G-3.

### G-17: PendingPanel "Coming in X" — developer pick numbers exposed to noob operators
**File:** `SRC/neothd-gui/ui/settings.slint:271-306`
**Category:** Audience mismatch
Tabs for Chat, Hemispheres, Channels, Skills, Plugins, Memory all display `"Coming in Pick #33"` or `"Coming in Pick #34 follow-up"`. Internal pick/sprint labels are invisible to noobs and break the product narrative.
**Fix:** Change `pending-pick` values to user-readable release identifiers: `"v0.2"`, `"next release"`, or a quarter like `"Q3 2026"`. Example: `"Coming in v0.2 — use the CLI mirror for now."`.

### G-18: `NeothButton` ⚙ icon — accessible label absent
**File:** `SRC/neothd-gui/ui/chat.slint:287-292`
**Category:** Accessibility / a11y
`NeothButton { label: "⚙"; }` renders a Unicode cog glyph as the label text. Screen readers (if ever supported) would announce "gear" or "⚙" with no context. The hit area is `width: 32px; height: 28px` — below the 44×44 pt desktop minimum.
**Fix:** Expand to 44×44 px. Replace the glyph label with an SVG icon inside an `Image { accessible-label: "Open Settings"; }` or add a `tooltip` property. At minimum keep `label: "⚙"` but add an `accessible-description` property to `NeothButton` that tools can read.

### G-19: Done screen — three buttons horizontally cramped
**File:** `SRC/neothd-gui/ui/main.slint:769-803`
**Category:** Layout / Button sizing
The Done screen footer has three `NeothButton` elements in one `HorizontalLayout`: "← Back", "Open Settings →", "Finish". At minimum window width 720 px − 64 px padding = 656 px for three buttons with `min-width: 120px` each = 360 px + 2 × 24 px spacing = 408 px fits, but the middle button's label "Open Settings →" is 14 characters at 15 px font ≈ 120 px min, so it can squeeze. On high-DPI or with font scaling it clips.
**Fix:** Move "Open Settings →" to a secondary action below the main row, or reduce it to an icon button. Keep only "← Back" and "Finish" in the footer row.

### G-20: ScreenHeader subtitle text density — descriptions below 12/10 standard
**File:** `SRC/neothd-gui/ui/main.slint` (multiple)
**Category:** Copy quality / Noob clarity
Several subtitles are too brief or developer-centric:
- Provider (line 434): `"Which LLM runs NEOTH's chat."` — noobs do not know what an LLM is.
- Autonomy (line 487): `"How much NEOTH may do without asking."` — correct sentiment but Strict/Full distinction is unclear.
- Keys (line 595): `"Stored in ~/.neoth/credentials.yaml at mode 0600."` — file path jargon is irrelevant to noobs.
**Fix examples:**
- Provider: `"Choose how NEOTH thinks. 'Local Qwen' runs fully offline — no internet needed. Others use a cloud service and need an API key."`
- Autonomy: `"Choose how independently NEOTH acts. 'Strict' asks before every file change. 'Full' trusts your policy file and never interrupts."`
- Keys: `"Your API key is stored securely on this computer, readable only by you. You can skip this and add it later."`

### G-21: KanbanTaskCard hemisphere badge — "unassigned" value not handled
**File:** `SRC/neothd-gui/ui/settings.slint:119-133`
**Category:** Edge case display
`KanbanTaskRow.hemisphere` documentation says `"left" | "right" | "cerebellum" | "unassigned"` but the color expression only branches on `cerebellum` and `right`. `unassigned` falls through to `Theme.text-muted` (same as `left`) and the badge text renders the full word "unassigned" (9 chars) inside a 56 px wide badge — clipped.
**Fix:** Add an explicit `unassigned` branch: `border-color` → `Theme.border-subtle`; badge text → `"—"`. Widen badge to 68 px to safely accommodate "cerebellum" (10 chars at 9 px ≈ 60 px + padding).

### G-22: Activity feed right rail — fixed 320 px width too large on 720 px window
**File:** `SRC/neothd-gui/ui/settings.slint:566-601`
**Category:** Layout at min-width
At 720 px window: 220 (sidebar) + 32 (padding) + 320 (feed) + 32 (spacing) = 604 px. The board columns get 720 − 604 − 32 (screen padding) = 84 px total for 5 columns. This is worse than the estimate in G-8 — the feed eats the board alive at min-width.
**Fix:** Change feed `width` to `min(320px, parent.width * 0.28)` so it shrinks proportionally.

**Category:** Consistency
`show-progress` correctly excludes `mode-selection` — the progress bar is hidden. But the `step-label` map still returns `"Choose your interface"` which appears in no rendered location. Low risk but the mapping adds dead code.

### G-24: ModeCard "RECOMMENDED" pill is 110 px wide, centered — fine, but not themed
**File:** `SRC/neothd-gui/ui/components.slint:258-275`
**Category:** Component polish
The pill uses hardcoded `width: 110px; height: 22px; font-size: 9px`. These are not theme tokens. If font scaling or DPI changes, the pill clips or drifts.
**Fix:** Express as `Text.preferred-width + Theme.space-base * 2` for width, `Theme.font-size-caption` for font-size, min-height 20 px.

### G-25: `TabButton` in settings — no hover state defined
**File:** `SRC/neothd-gui/ui/settings.slint:45-83`
**Category:** Interaction feedback
`TabButton` animates `background` on active but has no `hovered` state. On a desktop product with mouse, the absence of hover feedback makes the sidebar feel static.
**Fix:** Add `states [ hovered when touch.has-hover && !root.active: { background: Theme.bg-card.with-alpha(0.5); } ]` with `animate background { duration: Theme.duration-micro; ... }`.

### G-26: Window title stays "NEOTH — Setup" after transitioning to Chat
**File:** `SRC/neothd-gui/ui/main.slint:55`
**Category:** Title bar accuracy
After the wizard completes and the operator lands in Chat, the OS title bar still reads "NEOTH — Setup". Should update to `"NEOTH"` or `"NEOTH — Chat"`.
**Fix:** Drive `MainWindow.title` from the `step` property: `title: root.step == WizardStep.chat ? "NEOTH — Chat" : (root.step == WizardStep.settings ? "NEOTH — Settings" : "NEOTH — Setup");`

---

### G-27: Sovereign-Curve animations missing on screen transitions
**File:** `SRC/neothd-gui/ui/main.slint` (all step switches)
**Category:** Brand spec — motion
The spec mandates `duration: 600ms, easing: cubic-bezier(0.2, 0.8, 0.2, 1)` for screen changes. Current step transitions are instantaneous — the `if root.step == ...` conditional swap has no animation wrapper. Components animate their internal states but the screen-level enter/exit has no fade or slide.
**Fix:** Wrap each step's root element in a `Rectangle { opacity: 0; animate opacity { duration: Theme.duration-screen-min; easing: cubic-bezier(0.2, 0.8, 0.2, 1); } }` that transitions to `opacity: 1` on mount. Slint does not support exit animations natively — accept entry fade only.

## Confirmed Strengths

- **Card + ScreenHeader components** are well-structured, 12/10. Single-source of truth in `components.slint`, every screen uses them consistently.
- **Theme.slint** is exemplary: all tokens named, documented, no inline hex anywhere in wizard or chat code.
- **ProgressIndicator** animation is correctly sovereign-curved and fills left-to-right with the right semantics.
- **NeothButton** disabled state (opacity 0.4) is clear and consistent. The hover underline animation is subtle and on-brand.
- **FooterBar ANSI mitigation** (main.rs:558–563) shows the right instinct — NO_COLOR + RUST_LOG_STYLE on the hardware probe subprocess.
- **ChatBubble** role-based alignment (operator right / NEOTH left / system center) is correct UX pattern.
- **ConversationItem** unread badge and active-state accent bar are polished and appropriately minimal.
- **Done screen summary table** (key/value layout at line 660–759) is clean and operator-readable.
- **Back navigation** exists on every wizard step from License onward — correctly wired.
