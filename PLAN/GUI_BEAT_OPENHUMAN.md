## Analyses (what openhuman does well / NEOTH gaps)


### openhuman chat UX
- **strength:** Multi-bubble segmentation: every agent message is split at double-newlines via splitAgentMessageIntoBubbles (agentMessageBubbles.ts). Code fences and Markdown tables are never fragmented. isVisualSeparatorOnly silently drops hr/--- separators so visual cruft never renders as empty bubbles.
- **strength:** Bubble chrome geometry (format.ts getAgentBubbleChrome): a position enum (single/first/middle/last) drives border-radius classes so a multi-bubble reply looks like a conversation cluster.
- **strength:** Three-phase streaming pipeline: (1) isSending + no content => 3-dot bounce with 150ms stagger; (2) content.length > 0 => 120-char trailing monospace preview with blinking cursor; (3) thinking tokens => collapsible details block with pulsing dot. Each phase replaces the previous.
- **strength:** Streaming preview is intentionally plain text (not Markdown), documented in-source as avoiding 'jitter from partially-parsed fences'. Final bubble appears only on chat_done via addInferenceResponse, eliminating layout thrash.
- **strength:** Silence timer (120 s) that rearms on every inference signal via useEffect watching both inferenceStatusByThread and streamingAssistantByThread. Truly hung servers surface a typed error with code safety_timeout.
- **strength:** Socket-disconnect reconciliation in ChatRuntimeProvider: when socketStatus leaves connected, all in-flight lifecycle rows are ended immediately so the composer unlocks rather than waiting the full 2-minute silence timer.
- **strength:** Turn-state snapshot hydration (fetchAndHydrateTurnState): on thread switch the Rust core's persisted TurnState is loaded and dispatched via hydrateRuntimeFromSnapshot, re-materialising the tool timeline and streaming buffer. interrupted lifecycle is surfaced as a separate retry affordance, not fake live state.
- **strength:** Tool timeline (ToolTimelineBlock): each tool call is a details element. The latest running entry auto-opens. Status uses three-tone colours: amber (running), sage-green (success), coral (error). Sub-agent rows render SubagentActivityBlock with mode/dedicated-thread badges, live turn counter, elapsed time, and flat child-tool list.
- **standout:** The streaming preview is capped at 120 chars and shows only the trailing tail with an ellipsis prefix, giving a ticker-tape feel without layout jump when the final rendered bubble replaces it.
- **standout:** Bubble segmentation is entirely render-time (pure function, no server contract). Tables are auto-detected and rendered as full table elements with alternating row shading, not Markdown fallback.
- **standout:** The interrupted lifecycle (crash recovery) is first-class: snapshot hydrator suppresses fake live state for interrupted turns and surfaces only the tool timeline plus a retry affordance.
- **standout:** In-app navigation pills parsed from openhuman-link tags: clicking dispatches a custom window event rather than routing directly, keeping the chat in view while the destination panel opens.
- **standout:** Prompt injection guard runs client-side before every send. Results feed into sendAdvisory (amber warning, dismissible) vs sendError (red block) with data attributes for automated testing. It does not block sending on review verdict; only block verdict blocks.
- **adopt:** Three-phase streaming indicator: spinner -> trailing-tail monospace preview -> full rendered block, driven by a single StreamingState enum. NEOTH's TUI/GUI can follow the same ladder.
- **adopt:** Bubble segmentation as a pure render-time function. The isVisualSeparatorOnly filter + code-fence protection + table-group logic is 143 lines and directly portable to Rust as a line-iterator state machine.
- **adopt:** Bubble chrome geometry via a BubblePosition enum (single/first/middle/last driving border-radius or box-drawing characters in a TUI renderer).
- **adopt:** Silence timer with rearm-on-signal: a single timeout that resets on every inference event, not just on start. Prevents false-timeout during legitimate long tool chains. Applicable to NEOTH's Tokio-based turn watchdog.
- **adopt:** Turn-state snapshot hydration on thread/session switch. NEOTH already has WAL + turn state; projecting that onto the UI on resume or channel switch follows the same pattern: load persisted state, distinguish interrupted from live, surface timeline without fake live status for interrupted.
- **adopt:** Typed error codes with machine-readable attributes. NEOTH's error channel should carry an enum code so renderers can decide whether to show an action link, a plain retry, or nothing. The 13-code taxonomy from ChatSendErrorCode is a useful starting vocabulary.
- **adopt:** Citation chips as details elements: key + score% in summary, snippet in body. For NEOTH's recall surface this keeps citations non-intrusive until the user wants detail.
- **adopt:** Group-hover copy affordance offset to the bubble's outer edge. In NEOTH's TUI this maps to a key-binding hint visible only on the focused message row.

## Recommendations (ranked P0->P2, then effort)


### [P0 / XS / slint=YES] Replace raw CheckBox/LineEdit on License, Identity, and Channels wizard screens with NeothCheckBox/NeothLineEdit
- **Beats openhuman:** openhuman's boot gate and wizard never render platform-native white widgets against a dark background. NEOTH already solved this for the Provider/Autonomy/Settings screens via NeothComboBox/NeothCheckBox/NeothLineEdit — but the License screen uses `std-widgets::CheckBox`, the Identity screen uses `std-widgets::LineEdit`, and the Channels screen uses raw `CheckBox` for every channel row. On Windows these bleed bright white boxes into the dark UI on first launch, which is the first impression. The fix components already exist.
- **Sketch:** In main.slint: (1) License screen line 608: replace `CheckBox { text: 'I have read...'; checked <=> root.license-accepted; }` with `NeothCheckBox { text: '...'; checked <=> root.license-accepted; toggled(v) => { root.license-accepted = v; } }`. (2) Identity screen line 654: replace `LineEdit { placeholder-text: 'your-handle'; text <=> root.operator-id; edited(t) => ...; accepted(t) => ...; }` with `NeothLineEdit { placeholder-text: 'your-handle'; text <=> root.operator-id; edited(t) => ...; accepted(t) => ...; }`. (3) Channels screen lines 879/894/926-969: replace every `CheckBox { ... }` with `NeothCheckBox { ... }` — the API is identical. In settings.slint Cluster tab line 641: same swap for the mDNS CheckBox. Add `NeothCheckBox, NeothLineEdit` to the import in main.slint (they are already in components.slint). No Rust changes needed.
- _lens: SLINT FEASIBILITY / IMPLEMENTATION. Each recommendation maps an openhuman polish point to a concrete Slint primitive, identifies what needs a workaround, and flags any new subprocess JSON surface required from neothd._

### [P0 / S / slint=PARTIAL] Auto-scroll-to-bottom with manual-scroll opt-out
- **Beats openhuman:** Without auto-scroll every new streaming token requires the operator to manually scroll down, breaking the feel of a live feed. openhuman uses a triple-observer (layoutEffect + scroll-listener + ResizeObserver+MutationObserver). Slint's ScrollView exposes viewport-y; a Rust-side at_bottom bool + invoke_from_event_loop can pin the view on new message arrival and disengage when the operator scrolls up. This is the single most painful missing interaction in the current chat surface — fixing it makes NEOTH feel finished.
- **Sketch:** In chat.slint add a Rectangle anchor named scroll-anchor at the bottom of the VerticalLayout inside ScrollView. Expose a callback scroll-to-bottom() on ChatView. In main.rs, after every invoke_from_event_loop that pushes a new ChatMessage, call window.invoke_scroll_to_bottom() which sets a Slint property scroll-snap: bool. In chat.slint bind the ScrollView's viewport-y to: scroll-snap ? scroll-anchor.y - viewport.height : viewport-y (Slint 1.8 allows viewport-y as an in-out property on ScrollView). A FocusScope or TouchArea inside the ScrollView sets scroll-snap=false on pointer-down to implement the opt-out. Reset scroll-snap=true when a new message arrives.
- _lens: PRODUCT / UX. The biggest experience gaps NEOTH must close to feel as good as openhuman (chat polish, onboarding, navigation IA, empty/loading states, status surfacing), then the moves that make it BETTER for NEOTH's solo-operator + local-first niche. Prioritise what the operator FEELS._
