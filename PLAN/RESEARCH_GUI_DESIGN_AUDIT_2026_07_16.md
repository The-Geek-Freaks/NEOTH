## Animation & feedback polish — buddy.slint, overlay.slint, components.slint, app_shell.slint, main.slint

**Summary:** 26 of 27+ tabs switch with zero transition. BuddyDock mounts with no entrance spring. Mood changes animate only hue — the orb never physically reacts. The consent/alert badge is a dead static circle. Toast slides are fully absent (opacity-only). ConfirmDialog fades in but never rises. These are the gaps vs. Claude Desktop / beloved desktop companion quality.

- **[P0] 25 of 27 tabs switch with NO entrance animation** — Only the Chat tab is wrapped in SovereignFade (main.slint:3467). Every other tab — overview (L3510), resources (L3543), doctor (L3554), agents (L3572), memory, mesh, cron, dreaming, wiki, companion, WAL, all ProbeViews, etc. — is a bare `if root.nav-active == X: SomeView { ... }`. The component is unmounted and remounted on every switch. The SovereignFade and EntranceFade primitives (components.slint:545-568) exist specifically for this pattern. Fix: wrap every bare `if root.nav-active == "X":` block in `SovereignFade { ... }` at main.slint:3510–3940. This is a one-liner per tab and is the single largest visible regression vs. any modern companion app.
- **[P0] BuddyDock mounts with no entrance animation — orb just pops in** — main.slint:3948: `if root.buddy-visible: BuddyDock { ... }`. When buddy-visible flips true the orb appears at full size instantly. A beloved desktop companion (Claude Desktop, Notchmeister, Tamagotchi) spring-scales in from 0 → 1.0 with a 400ms overshoot. Fix: wrap the `BuddyDock` instantiation in a Rectangle that starts at `opacity: 0; scale-x: 0.6; scale-y: 0.6` on init and springs to 1.0. In Slint, approximate by initializing `width/height` of a wrapper to 0 and animating to orb-size with `easing: cubic-bezier(0.34, 1.56, 0.64, 1)` (the same spring already used for the nav rail at app_shell.slint:59). BuddyDock has no `init` hook and no `animate` declarations of its own (buddy.slint:414–454).
- **[P0] Mood change animates only hue — the orb never physically reacts** — buddy.slint:56–57: `property <color> hue: root.hue-target(); animate hue { duration: 300ms; ... }`. That is the only animated property on a mood switch. The root `orb-size` is static. The `pop` term at L110–L111 is a continuous oscillation (350ms period), not a one-shot state-entry overshoot. Claude Desktop's orb briefly scales to ~1.08x and springs back every time mood changes. Fix: add `property <float> mood-pop: 1.0;` on Buddy root; on `changed mood` fire `self.mood-pop = 1.08;` then `self.mood-pop = 1.0;` with `animate mood-pop { duration: 380ms; easing: cubic-bezier(0.34, 1.56, 0.64, 1); }`, and multiply into `core-scaled` and all child x/y calculations.
- **[P0] Toast entrance is opacity-only — the CSS x-slide is entirely missing** — components.slint:624–630: the comment explicitly acknowledges the loss — 'The CSS nh-toast-in translateX(30px→0) cannot fire because Toast is a VerticalLayout child — the layout engine owns x.' This is fixable: remove ToastStack's VerticalLayout child model and instead render each Toast as an absolute-positioned element inside a clip Rectangle, stacked by index. Each Toast can then have `x: 30px → 0` with `animate x { duration: Theme.duration-toast-in; easing: cubic-bezier(0.16,1,0.3,1); }` on init. The ToastStack component (L683–704) currently uses a VerticalLayout for the for-loop — change to explicit absolute stacking with `y: i * (card-height + 8px)` and individual `x` springs.
- **[P1] Consent/alert badge is a dead static circle — no urgency animation** — buddy.slint:371–376: the pink '!' badge for `mood == 'alert' || mood == 'consent' || mood == 'problem'` is a static Rectangle. There is no breathe, throb, or scale pulse. Claude Desktop and every iOS notification badge uses a radial scale throb for urgent states. Fix: add `opacity: 0.75 + 0.25 * root.breathe;` and `width/height: 12*u * (1.0 + 0.12 * root.breathe);` to the badge, centering via `x: (62 + 0.06*50*(1-self.width/(12*root.u))) * root.u`. For mood='consent' specifically, add a second larger ghost circle (20u, alpha 0.15) that breathes out-of-phase — the 'ring spreading outward' effect seen in macOS permission dialogs.
- **[P1] ConfirmDialog: only opacity fade, no y-rise spring** — components.slint:1419–1427: `dlg-card` fades opacity 0→1 over `duration-fast` (120ms). No vertical motion. The industry standard (Linear, Notion, Claude Desktop) is a 6–8px upward rise simultaneous with the fade, using the sovereign curve. Fix: add `property <length> dlg-y-offset: 8px; init => { self.dlg-y-offset = 0px; } animate dlg-y-offset { duration: Theme.duration-entrance; easing: cubic-bezier(0.16,1,0.3,1); }` and use `y: (root.height - self.height) / 2 + dlg-y-offset` on dlg-card. This is three lines. The scrim background also has no fade — it appears instantly at full alpha. Fix: `opacity: 0; init => { self.opacity = 1; } animate opacity { duration: Theme.duration-fast; easing: ease-out; }` on the ConfirmDialog root.
- **[P1] Sidebar Buddy orb hardcoded to mood='idle' — never reflects real app state** — app_shell.slint:158: `Buddy { mood: "idle"; orb-size: 34px; show-face: true; }`. The 34px brand-bar buddy always shows idle regardless of what the daemon is doing. Claude Desktop's window-chrome orb tracks activity in real time — that's the 'living companion' contract. Fix: add `in property <string> buddy-mood: "idle";` to the Sidebar component signature (app_shell.slint:127) and pass it through from the call-site at main.slint:3018 (which already has `active-tab: root.nav-active` wiring). Then at L158 change to `Buddy { mood: root.buddy-mood; ... }`. The Rust side already provides `buddy-mood` globally (main.slint:457).
- **[P1] Notification/unread badge appears and disappears with no animation** — overlay.slint:242–269 (compact pill badge) and overlay.slint:443–470 (title bar badge): both are `if root.unread-count > 0: Rectangle { ... }`. They mount and unmount with no spring or fade. On every new message the badge just blinks into existence. Fix: replace the `if` with a permanent Rectangle that uses `opacity: root.unread-count > 0 ? 1.0 : 0.0; animate opacity { duration: Theme.duration-fast; ... }` and `width/height` that animate from 0 to 16px with a spring curve. Bonus: on count increment the badge should briefly scale to 1.3x — track the previous count with a `changed unread-count` handler that sets a `pop-scale` to 1.3 then 1.0.
- **[P2] BuddyDock caption chip text changes instantly — no cross-fade** — buddy.slint:447: `lbl := Text { text: root.caption; ... }`. When `caption` changes on mood switch the label snaps. Beloved desktop companions cross-fade captions. Fix: add a second `Text` node (lbl-prev) with the previous caption value, fading out while `lbl` fades in. Use a `changed caption` handler to trigger the swap: `lbl.opacity = 0; lbl-prev.opacity = 1; lbl.opacity = 1; lbl-prev.opacity = 0;` with `animate opacity { duration: Theme.duration-fast; ... }` on both. Because the caption chip is a `Rectangle` (not a layout child), both texts can be absolute-positioned on top of each other trivially.
- **[P2] Mood overlay elements have no entrance fade — thinking dots and scan bar pop in** — buddy.slint:327–338 (thinking dots block) and buddy.slint:341–360 (working scan bar block): both use `if root.is-mood(...): Rectangle { for ... }` with no `init` hook. When the mood changes to 'thinking', the three dots appear at full opacity. Fix is minimal — add `opacity: 0; init => { self.opacity = 1; } animate opacity { duration: 200ms; easing: ease-out; }` to the outer wrapper Rectangle of each block. The scan bar's outer Rectangle already has `property <float> sweep` so just add the opacity init on the container. The 'success' checkmark at L363–368 (Path) also has no entrance — add the same pattern.
- **[P2] Overlay scrollback: new message lines appear with no entrance stagger** — overlay.slint:592–603: `for line[i] in root.recent-lines: Text { ... }` renders every line simultaneously with no per-item animation. When a new line arrives the whole list re-renders. A beloved companion (Navi, Clippy's modern heirs) slides in the newest message. Fix: wrap each `Text` in a minimal `Rectangle { opacity: 0; init => { self.opacity = 1; } animate opacity { delay: i * 40ms; duration: 280ms; easing: ease-out; } }`. This gives a cascading reveal. The newest message (last index) arrives with a 40ms-per-slot delay chain producing a natural 'typing cascade' read.
- **[P2] Loading states in ProbeView/StatRow use text '—' instead of Skeleton shimmer** — tabs.slint:127: ProbeView uses Skeleton while `running && output == ''` — that part is correct. But StatRow (tabs.slint:10–32) shows '—' as value with no shimmer during the first hardware probe. The ResourcesView (tabs.slint:36–88) mounts all StatRows immediately with '—' values. Fix: add an `in property <bool> loading: false` to StatRow and render a Skeleton component (1 row, matching height) instead of the value Text when `loading` is true. ResourcesView then passes `loading: root.cpu == ''` etc. The Skeleton shimmer (components.slint:1528) already has the correct sweep animation and accessible-label 'Loading…'.
- **[P3] Overlay 'companion ready' placeholder should be a Skeleton while connecting** — overlay.slint:583–590: while `recent-lines` is empty and `daemon-state == 'connecting'`, the scrollback shows static text '— companion ready —'. A loading shimmer communicates that content is incoming rather than that the session is empty. Fix: replace the static `if root.recent-lines.length == 0: Text { ... }` with `if root.recent-lines.length == 0 && root.daemon-state == 'connecting': Skeleton { rows: 3; ... }` and a separate `if root.recent-lines.length == 0 && root.daemon-state != 'connecting': Text { ... }` for the settled empty state.
- **[P3] TopBar title text snaps on tab switch — no cross-fade** — app_shell.slint:328–336: `Text { text: root.title; ... }` — the title changes instantly when `nav` fires. Fix: use the same dual-Text cross-fade approach. Track `prev-title` with a `changed title` handler: fade `title-a` (showing old text) to 0 while `title-b` (showing new text) fades to 1, then swap roles. With `duration: Theme.duration-fast` (120ms) this is nearly imperceptible but eliminates the snap. The TopBar `kicker` text has the same issue.

## GUI interaction-grammar — list rows (AGENTER)

**Summary:** Audited chat.slint, settings.slint, cron.slint, mesh.slint, agents_view.slint. Zero list rows have keyboard navigation (no FocusScope + key-pressed anywhere). KanbanTaskCard is the only component with right-click partially wired (callback fires, no PopupWindow mounted). Skills is the only list with filter-as-you-type. Every other list (9 total) is missing all three interaction primitives: right-click context menu, filter, keyboard nav.

Missing ContextMenu items: Rename, Copy ID, Delete, Pin to top. CLI backing: `neoth session rename <id>`, `neoth session delete <id>` (verify these exist in cli/session.rs). No filter above the list — 10+ sessions require scroll-hunt. No FocusScope. Highest-frequency interaction surface in the app.

No filter NeothLineEdit above the job list — jobs accumulate. CLI: `neoth cron edit <id>`, `neoth cron remove <id>`, `neoth cron run <id>`. No keyboard nav.
- **[P1] Channel sidebar (chat) — no right-click, no keyboard nav** — chat.slint:~972 — `ConversationItem` component / `for ch[idx] in root.channels`. TouchArea wires only `clicked`. Missing ContextMenu: Copy channel name, Pin, Disconnect/Remove, Mark unread. CLI: `neoth channel disconnect <name>`. Channel count is bounded but pin/copy-id are daily ops. - **[P1] Plugin rows (settings) — no filter, no right-click** — settings.slint:~2102 — `for p in root.plugins`. Unlike Skills (which has `skills-filter` NeothLineEdit at line ~1949), plugins have no search box. - **[P1] Memory blocks (settings) — no filter, no right-click** — settings.slint:~2277 — `for m in root.memory-blocks`. Read-only rows (source/path/bytes). No filter. Missing right-click ContextMenu: Copy Path, Copy Topic, Forget/Evict block. CLI: `neoth memory forget <topic>`. Memory can grow large; filter is essential for targeted eviction. No keyboard nav.
- **[P1] KanbanTaskCard right-click — callback wired, PopupWindow not mounted** — settings.slint:~274 — `pointer-event(ev)` checks `PointerEventButton.right && PointerEventKind.up` and fires `root.context-menu(x, y)`. Missing menu items per Linear/Notion standard: Rename, Copy ID, Change status, Move to column, Duplicate, Delete. This is the most complete starting point — wire the PopupWindow here first.
- **[P2] Skills rows (settings) — has filter, no right-click** — settings.slint:~1979 — `for s in root.skills`. Filter at line ~1949 via `skills-filter` NeothLineEdit is present (only list with this). Missing right-click ContextMenu: Copy ID, Enable/Disable toggle, Uninstall (shortcut vs scrolling to button), View config. CLI: `neoth skills --enable <id>`, `neoth skills --disable <id>`, `neoth skills --uninstall <id>`. No keyboard nav.
- **[P2] Channels settings list — no filter, no right-click** — settings.slint:~1608 — `for c[index] in root.channels`. Configure/Test/Remove inline buttons. No filter. Missing right-click ContextMenu: Copy channel name, Test connection, Reconfigure, Remove. CLI: `neoth channel test <name>`, `neoth channel remove <name>`. No keyboard nav.
- **[P2] Mesh PeerCard — no filter, no right-click** — mesh.slint:51 (component) / 529 (for loop). Peer cards show 'Request Sync' + 'Details' expand only. Missing right-click ContextMenu: Copy peer ID, Copy endpoint, Request Sync, Remove peer. No filter above peer list. CLI: `neoth cluster sync <peer-id>`, `neoth cluster topology`. - **[P2] Agent cards (agents_view) — no right-click, no filter** — agents_view.slint:161 (AgentCard) / 351 (for loop). Cards display agent name, hemisphere, provider/model, state, task. No right-click ContextMenu: Copy agent ID, Copy model string, Kill task, Restart agent. No filter above the card list (hemisphere or state filter would be high-value). - **[P3] Preset list (settings) — no filter, no right-click** — settings.slint:~4296 — `for p in root.preset-list`. Apply + Delete inline. Missing right-click ContextMenu: Copy preset name, Apply, Duplicate, Delete. No filter. CLI: `neoth preset apply <name>`, `neoth preset delete <name>`. Low row count typically, hence P3.
- **[P3] Universal — zero list rows have keyboard navigation** — No `FocusScope` + `key-pressed` handler found in any list component across chat.slint, settings.slint, cron.slint, mesh.slint, agents_view.slint. Arrow-key navigation (Up/Down to move selection, Enter to activate, Delete to remove) is absent everywhere. ## SRC/neothd-gui/ui — all .slint files

**Summary:** Sweep of 18+ Slint files against six homogeneity categories. Two accessibility P0s (NavBtn + ConversationItem have no accessible-* at all). One P1 accessibility cluster (six more interactive elements missing accessible-role/label/action-default). One P1 token-floor cluster: raw 9 px and 10 px font-size literals appear in 40+ call-sites across 12 files — both values are below the system's minimum token (font-size-2xs = 11 px). Five more P2 findings: Toast component raw font-sizes in components.slint; chat.slint 56 px glyph; app_shell StatusFooter 8x raw 11 px; empty-state violations in overview (5x), activity, wal_inspector, and mesh; and mesh PeerCard Details missing accessible-action-default. P3 residuals: buddy.slint raw font-weight int, systemic off-grid spacing, overlay raw border-radius literals.

- **[P0] NavBtn — zero accessible-* on primary navigation** — NavBtn (app_shell.slint:32-97) has only `TouchArea { clicked => root.clicked(); }` at L96. No accessible-role, accessible-label, or accessible-action-default anywhere on the component or its container. Every sidebar navigation button is invisible to screen-readers and keyboard-only users. Fix: add `accessible-role: button; accessible-label: root.label + " navigation"; accessible-action-default => { root.clicked(); }` to the root Rectangle (or to the TouchArea).
- **[P0] ConversationItem — interactive list row has no accessible-*** — chat.slint:518-597, `touch := TouchArea { clicked => root.clicked(); }` at L594. - **[P1] Theme-toggle Rectangle — interactive but zero accessible-*** — app_shell.slint:301-312 — `ta := TouchArea { clicked => { Theme.dark = !Theme.dark; root.toggle-theme(); } }` at L310 with no accessible-role or accessible-label on the Rectangle.
